# PC Monitor на ESP32-2432S028 (CYD, вариант 2USB)

Дашборд температур и загрузки ПК на 2.8" TFT + частичное управление:
автоматическое и ручное включение реле по порогам, команды ПК
(сон / перезагрузка / выключение) прямо с экрана.

```
┌──────────────────────────────────────────────┐
│ PC MONITOR        UP 07:02:11       ONLINE   │
│ ┌────────────┐ ┌────────────┐               │
│ │CPU 52.3 C  │ │GPU 63.1 C  │               │
│ │3.45GHz 63W │ │1.98GHz 185W│               │
│ │L ▓▓▓░░ 42% │ │L ▓▓▓▓▓ 88%│               │
│ └────────────┘ └────────────┘               │
│ RAM 48% ▓▓▓▓▓░░░░░░░░      15.9GB           │
│ FANS           │ DISK C 62%                 │
│ 1: 900         │ free 93 GB                 │
│                │ dn 12.4 Mb  up 3.1 Mb      │
│ [DASH] [GRAPHS] [CTRL] [CORES]              │
└──────────────────────────────────────────────┘
```

## ⚠️ Важно про железо (вариант 2USB)

У CYD с двумя USB-разъёмами (micro-USB + USB-C) **другая распайка**, чем у
классической версии с micro-USB (ESP32-2432S028**R**):

| | Классическая (R) | **2USB (этот проект)** |
|---|---|---|
| Контроллер TFT | ILI9341 | **ST7789** |
| Шина TFT | HSPI | HSPI, **другие пины** |
| Тач XPT2046 | общая шина с TFT | **отдельная шина VSPI** |

Прошивка настроена под **2USB**. Если экран остаётся чёрным / цвета инвертированы
— см. раздел «Диагностика».

### Карта пинов CYD 2USB

| Назначение | GPIO |
|---|---|
| TFT (ST7789): MISO / MOSI / SCLK / CS / DC | 12 / 13 / 14 / 15 / 2 |
| Подсветка TFT (BL) | 21 |
| Тач XPT2046: CLK / MOSI / MISO / CS / IRQ | 25 / 32 / 39 / 33 / 36 |
| RGB-светодиод R / G / B (активный низкий) | 4 / 16 / 17 |
| Зуммер | 26 |
| Датчик освещённости (LDR) | 34 (input-only) |
| microSD | CS = 5 (общая шина VSPI с тачем) |
| **Свободные разъёмы** | **22, 27, 35 (35 — только вход)** |

## Возможности

- **8 страниц**: дашборд, графики за 120 с (температуры/нагрузки CPU/GPU + RAM/диск),
  управление, **CORES** (температуры ядер крупными блоками со спарклайнами истории
  за 120 с и максимумом), **KEYS**, **MEDIA**, **APPS** и **PROCS**:
  - **MEDIA** — кнопки мультимедиа для ПК: mute, громкость −/+, предыдущий трек,
    play/pause, следующий трек, **«сейчас играет»** (название трека из окна
    десктопных плееров: Spotify/foobar/VLC/Winamp/AIMP…) и **реальный уровень
    громкости** Windows с полосой (mute подсвечивается);
  - **APPS** — **быстрый запуск приложений**: 8 кнопок запускают программы на ПК.
    Список (подпись + команда/путь к .exe/.lnk/URL) задаётся в окне ПК кнопкой
    **«Запуск APPS…»** (с выбором файла «Обзор…»), на экран уходят только подписи
    (`AP:n=label`), команды исполняет ПК-приложение (`APP:n`);
  - **PROCS** — **топ-5 процессов по CPU** (имя, загрузка, память МБ) и кнопка
    **KILL** на строку: первый тап — подтверждение (кнопка краснеет «SURE?»),
    второй в течение ~2.5 с — процесс завершается (`KILL:pid` → taskkill /F);
  - **KEYS** — 8 **настраиваемых горячих клавиш** (например TaskMgr = Ctrl+Shift+Esc,
    Desktop = Win+D): подпись и комбинацию меняют в приложении на ПК (кнопка
    **«Клавиши KEYS…»**) **или прямо на экране**: удерживайте кнопку KEYS ~0.7 с —
    откроется встроенный редактор (модификаторы CTRL/ALT/SHIFT/WIN, клавиши
    A-Z / 0-9 / F1-F12 / служебные), SAVE сохраняет во флеш и синхронизирует с ПК
    (строка `HKCFG:n=label|combo`); конфиг хранится во флеш-памяти ESP32
- **Датчики ПК**: температуры CPU/GPU/**материнки (SYS)**, загрузка, частоты, мощности, RAM,
  вентиляторы, скорость сети, напряжение 12V (если есть), **занятость/свободное место диска C:**,
  аптайм. Температура SSD требует прав администратора (SMART) — на экран выводится
  SYS-датчик материнки вместо неё
- Правая нижняя ячейка дашборда **адаптивная**: если плата отдаёт 12V — показывает его,
  иначе показывает **занятость диска C:** с процентом и свободным местом
- **Графики**: верхняя панель — температура CPU (красный), **средняя по ядрам (оранжевый)**,
  загрузка CPU (голубой), RAM % (жёлтый);
  нижняя — температура GPU (зелёный), загрузка GPU (пурпурный), диск % (голубой).
  Справа в каждой панели — **живая легенда**: цветная точка, имя серии и текущее
  значение, обновляющееся раз в секунду
- **Визуальный отклик на тап**: нажатая кнопка KEYS/APPS/MEDIA подсвечивается яркой
  рамкой (~130 мс), экран реагирует мгновенно (страницы перерисовываются сразу,
  без ожидания следующей секунды)
- **Индикаторы-шкалы**: загрузка/RAM/громкость — скруглённые «пилюли» с зонной
  заливкой (зелёный 0-55%, жёлтый 55-85%, красный 85%+); спарклайны CORES получили
  мягкую цветную подложку под кривой
- **Управление**:
  - 2 реле (GPIO22 и GPIO27): ручное переключение с экрана + **авто-режим по порогам
    с гистерезисом** (реле 1 — по температуре CPU, реле 2 — по GPU)
  - **Пороги AUTO-реле и тревог редактируются из ПК-приложения** (кнопка **«Пороги…»**
    в окне приложения и в трее): R1/R2 вкл-выкл, WARN и ALARM — уходят строкой
    `THR:r1on=…,r1off=…,r2on=…,r2off=…,warn=…,crit=…`, хранятся во флеше ESP32
    (NVS, namespace `thr`) и применяются **без перепрошивки** (экран, тревоги, реле);
  - **всплывающие уведомления на ПК** при пересечении порогов WARN/ALARM (CPU/GPU)
    с записью в журнал приложения — без спама: одно на вход в зону + одно на возврат в норму
  - GPIO35 — свободный вход (например, концевик или кнопка) — задел на будущее
  - кнопки SLEEP / REBOOT / SHUTDOWN — команда уходит на ПК по USB-Serial
- **Цветовые зоны** для температур и загрузки (зелёный/жёлтый/красный)
- **Тревоги (RGB-светодиод 4/16/17 + зуммер GPIO26)**:
  - зелёный — норма; жёлтый — предупреждение; **красный мигающий + сигнал** — перегрев
    (пороги WARN/ALARM по умолчанию 60/75 °C — **настраиваются кнопкой «Пороги…»** в ПК-приложении)
  - **синий мигающий + «бип-бип»** — ПК офлайн (пропала связь)
  - звук отключается кнопкой **ALARM** на странице **CTRL** (выбор запоминается во флеш-памяти);
    RGB-индикация продолжает работать и при выключенном звуке
- **Индикация ONLINE/OFFLINE** — если данные от ПК пропали более чем на 3 секунды
- **Сторожевой таймер**: если прошивка зависнет — контроллер сам перезагрузится через 8 с
  (аппаратный watchdog, esp_task_wdt)
- **Калибровка тача** на экране (мастер при первом запуске + кнопка TOUCH на странице
  управления); тач работает по «давлению» (z), IRQ не обязателен

## Прошивка (PlatformIO)

1. Установите [PlatformIO Core](https://platformio.org/install) (`pip install platformio`).
2. Соберите и залейте (в обычном PowerShell/cmd; **из Git Bash** сначала уберите
   переменную `MSYSTEM`, иначе `idf_tools.py` откажется работать):
   ```bash
   pio run -t upload
   ```
   Монитор порта:
   ```bash
   pio device monitor
   ```
3. **При первом запуске** запустится мастер калибровки тача: коснитесь креста и
   **удерживайте ~0.2 с** — появятся подсказки «Touch 1/2», «Touch 2/2» (2 точки).
   Калибровка сохраняется во флеш-памяти.

   **Если тач «поехал» или не реагирует** — самолечение без ПК: **удерживайте палец
   ~3 секунды в любом пустом месте экрана** (не на кнопке) — запустится мастер
   калибровки. Сработает даже при «кривой» сохранённой карте, т.к. отсчёт идёт по
   факту касания. Альтернатива — кнопка **TOUCH** на странице **CTRL**. Если совсем
   не помогает: `pio run -t erase -t upload`, затем повторите калибровку.

> Компиляция проверена с `espressif32` + `TFT_eSPI 2.5.x` (ST7789) +
> `XPT2046_Touchscreen`. Настройка дисплея задаётся через `build_flags` в
> `platformio.ini` (пины — из официального конфига witnessmenow/DisplayConfig/CYD2USB).

## Подключение реле

Реле подключаются к **GPIO22** и **GPIO27** через модуль с оптопарой
(или транзисторный ключ):

```
ESP32 GPIO22 ──► IN1 (оптопара реле 1 — вентиляторы корпуса, порог по CPU)
ESP32 GPIO27 ──► IN2 (оптопара реле 2 — доп. охлаждение GPU, порог по GPU)
ESP32 GND    ──► GND модуля реле
ESP32 5V/VIN ──► VCC модуля реле (или отдельный БП с общим GND)
```

- **Коммутируйте только низковольтные нагрузки** (вентиляторы +12V) или сеть 220V
  через контакты реле (COM/NO) — никогда не подключайте сеть к GPIO ESP32!
  Работайте с сетью 220V только при отключённом питании.
- GPIO35 — input-only, выходом быть не может.

## Данные с ПК

### Способ 1 (рекомендуется): готовое Windows-приложение `CYD-PC-Monitor.exe`

Всё в одном .exe (~27 МБ), **ничего устанавливать не нужно** (Python не требуется):

1. Запустите `pc\dist\CYD-PC-Monitor.exe` двойным кликом.
2. Приложение само:
   - найдёт (или распакует встроенную копию в `%LOCALAPPDATA%\CydMonitor`) и запустит
     **LibreHardwareMonitor** с автоматически включённым веб-сервером датчиков;
   - найдёт ESP32 по USB (CH340) и начнёт слать датчики на экран раз в секунду;
   - покажет статус и значения в окне, свернётся в **трей** при закрытии окна;
   - включится **вместе с Windows** (галочка «Старт с Windows»).

Окно приложения: индикатор связи, значения CPU/GPU/RAM/вентиляторов/сети,
журнал, кнопка **Пуск/Стоп**. В трее — меню: показать окно, пуск/пауза, выход.

**Автозапуск LHM при входе в Windows — БЕЗ единого окна UAC.**
LibreHardwareMonitor должен работать с правами администратора (полный набор датчиков),
поэтому он стартует не из приложения, а **задачей Планировщика Windows**
`CYD-LibreHardwareMonitor` (LogonTrigger, RunLevel=Highest): Windows сама поднимает
процесс с админ-правами в момент входа — молча, без окон подтверждения.

- задача регистрируется один раз (нужны права администратора — либо автоматически
  при первом запуске приложения, либо вручную:
  `schtasks /Create /TN CYD-LibreHardwareMonitor /TR "\"D:\LibreHardwareMonitor\LibreHardwareMonitor.exe\"" /SC ONLOGON /RL HIGHEST /F`);
- приложение само добавляется в автозапуск (ключ реестра `...\Run`, старт в трее с `-t`);
- LHM стартует **свёрнутым в трей** (`startMinMenuItem`/`minTrayMenuItem=true` в его конфиге);
- чтобы LHM поднимался быстрее, в конфиге отключён опрос ненужных экрану подсистем
  (сеть, диски, БП, батарея — `nicMenuItem`/`hddMenuItem`/`psuMenuItem`/`batteryMenuItem=false`);
- приложение стартует мониторинг **сразу** (загрузка CPU/RAM/сеть — из psutil), а полный
  набор датчиков подключается сам, как только веб-сервер LHM ответит на :8085
  (проверка каждые ~5 с, переподключение бесконечное).

Журнал дублируется в `%LOCALAPPDATA%\CydMonitor\app.log`.

Полный набор датчиков (температуры CPU/GPU, вентиляторы, мощности, частоты) приложение
берёт из LHM по `http://127.0.0.1:8085/data.json`; базовые (загрузка CPU, RAM, сеть,
частота, аптайм) — из `psutil`, так что часть данных видна даже без LHM.

Пересобрать .exe после правок: `pc\build_exe.bat` (нужен PyInstaller:
`pip install pyinstaller pystray`).

### Способ 2: консольный скрипт (Python)

1. Установите зависимости:
   ```bash
   pip install -r pc/requirements.txt
   ```
2. Если хотите полный набор датчиков — запустите LHM **от администратора** с веб-сервером
   (см. ниже). Приложение/exe это делает автоматически; скрипту можно подсказать:
   ```bash
   python pc/pc_monitor.py --lhm   # сам найдёт/запустит LHM и подождёт веб-сервер
   python pc/pc_monitor.py         # обычный запуск (полный бэкенд подключится позже)
   python pc/pc_monitor.py --port COM3
   ```
3. Подключите CYD к ПК кабелем в разъём, на котором сидит CH340.

Скрипт читает датчики из LHM и каждые ~5 с **автоматически переподключается**, если
LibreHardwareMonitor запустить позже. Запасные источники: WMI (`root\LibreHardwareMonitor`),
`nvidia-smi`, `psutil`.

**Ручная настройка LHM (если делаете без приложения):** распакуйте
[LibreHardwareMonitor](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor)
(проверено v0.9.6) в `D:\LibreHardwareMonitor`, запустите **от администратора** и включите
веб-сервер: меню **Options → Remote Web Server → Run** (настройка сохранится в конфиге
`runWebServerMenuItem=true`). Порт 8085 зарезервируйте один раз:
`netsh http add urlacl url=http://+:8085/ user=<ваш_пользователь>`.

> **Проверено:** на некоторых машинах LHM при «холодном» старте не сразу поднимает
> веб-сервер (первичный опрос железа занимает минуты, а при повторных запусках после
> аварийных завершений драйвер доступа к датчикам может «залипнуть» до перезагрузки
> Windows). Если после входа в систему датчики не появились в течение ~5 минут —
> нажмите в окне приложения **«Запустить LHM»** (перезапустит LHM через задачу) или
> перезагрузите ПК: после чистой загрузки LHM стартует задачей автоматически.

### Способ 3: Linux

```bash
pip install -r pc/requirements.txt
python pc/pc_monitor.py
```
CPU-температура: `psutil.sensors_temperatures` (coretemp/k10temp); GPU: `nvidia-smi`
(для AMD без nvidia-smi температура GPU может отсутствовать — остальное работает).

## Протокол (ASCII, 115200 8N1)

ПК → ESP32, строка `key=val,key=val,...\n` раз в секунду (любые поля можно опускать):

```
cpu_temp=52.3,gpu_temp=63.1,cpu_load=42.5,gpu_load=88.0,cpu_freq=3450,gpu_freq=1980,
cpu_power=63.5,gpu_power=185.2,ram_pct=48.3,ram_total_gb=15.9,
fan1=900,fan2=1200,net_dn=12.4,net_up=3.1,v12=11.98,
disk_pct=62.5,disk_free_gb=93.2,uptime=25341
```

ESP32 → ПК: `CMD:sleep` | `CMD:reboot` | `CMD:shutdown`

## Настройка под себя

Большая часть «поведенческих» настроек — **без перепрошивки**, из ПК-приложения:

- горячие клавиши — кнопка **«Клавиши KEYS…»** (или редактор на самом экране);
- список быстрого запуска — кнопка **«Запуск APPS…»**;
- **пороги AUTO-реле и тревог — кнопка «Пороги…»** (вкл/выкл реле 1 и 2 по CPU/GPU,
  зоны WARN/ALARM). Применяются мгновенно: экранные цвета, RGB-тревоги и авто-реле
  работают по новым значениям без перепрошивки; значения хранятся во флеше ESP32.

«Железные» вещи — в одном файле `include/config.h`:

- пины реле (`RELAY1_PIN` = 22, `RELAY2_PIN` = 27)
- **стартовые** пороги (если ПК ещё не присылал свои): `RELAYx_ON_TEMP`/
  `RELAYx_OFF_TEMP`, `TEMP_WARN_C`, `TEMP_ALARM_C`
- таймаут OFFLINE (`DATA_TIMEOUT_MS`), период обновления (`UI_REFRESH_MS`)
- пины тача (`TOUCH_*`) — если у вашей ревизии 2USB они отличаются
- пины RGB/зуммера (`RGB_R_PIN`/`RGB_G_PIN`/`RGB_B_PIN`/`BUZZ_PIN`)

Паттерны тревог (длительности мигания и сигналов) — константы в начале `src/alarm.cpp`.

> Примечание: прошивка стартует с порогов из `config.h`, затем применяет
> сохранённые во флеше значения (если ПК их менял). Чтобы вернуть заводские —
> в приложении «Пороги…» введите дефолты или удалите namespace `thr` в NVS.

## Диагностика

| Проблема | Решение |
|---|---|
| Чёрный экран | Вероятно, у вас классическая R-ревизия (ILI9341): в `platformio.ini` замените `ST7789_DRIVER` на `ILI9341_DRIVER`, уберите `TFT_RGB_ORDER`/`TFT_INVERSION_OFF`, пины TFT: MISO=12 MOSI=13 SCLK=14 CS=15 DC=2 BL=21 — и добавьте `-DTOUCH_CS=21` (у R-версии тач на общей шине; тогда из `display.cpp` уберите отдельный `touchBus`) |
| Экран есть, цвета инвертированы | В `platformio.ini` замените `TFT_INVERSION_OFF` на `TFT_INVERSION_ON` (бывает на части партий ST7789) |
| Красный/синий перепутаны | Уберите строку `-DTFT_RGB_ORDER=TFT_BGR` (или поставьте `TFT_RGB`) |
| Не находится COM-порт | Установите драйвер CH340; проверьте порт в Диспетчере устройств; укажите `--port` |
| OFFLINE на экране | Запущен ли `CYD-PC-Monitor.exe` (или `pc_monitor.py`)? Работает ли LHM? Смотрите журнал приложения (`%LOCALAPPDATA%\CydMonitor\app.log`) |
| Приложение запустилось, но данные не идут | Откройте окно, нажмите **Пуск**; проверьте, что выбран порт CH340 (кнопка ⟳ обновляет список); журнал покажет ошибки |
| Нет температуры CPU/GPU | Проверьте датчики в LibreHardwareMonitor; скрипт печатает совпавшие значения — см. `--debug` |
| Страница CORES пустая (--) | Данные по ядрам даёт только LibreHardwareMonitor: включите веб-сервер LHM (кнопка «Запустить LHM» в окне приложения) и подождите ~30 с |
| Нет температуры SSD | SMART-датчики без прав администратора недоступны; на экране показывается температура материнки (SYS) |
| MEDIA/KEYS/APPS не нажимаются | Проверьте, что приложение на ПК запущено и COM-порт открыт (кнопки шлют команды на ПК по USB); комбинации в KEYS меняются кнопкой **Клавиши KEYS…** или удержанием кнопки KEYS на экране 0.7 с (редактор на борту); приложения на вкладке APPS настраиваются кнопкой **Запуск APPS…** |
| Тач не реагирует | **Удерживайте палец 3 с в пустом месте** (запустится мастер) или нажмите TOUCH на CTRL; проверьте, что не занят GPIO33/25/32/39 |
| Тач «сам нажимает» или калибровка проскочила без касаний | Обновите прошивку (мастер теперь требует устойчивое нажатие ~0.1 с и отпускание); если нужно — `pio run -t erase -t upload` |
| Калибровка «уезжает» | Оси тача на некоторых партиях переставлены — мастер это детектит автоматически; повторите калибровку ещё раз |

## Готовые альтернативы

Если хочется не писать, а взять готовое:

- **AIDA64 + LCD** — есть встроенная поддержка вывода датчиков на внешний дисплей (классика для маленьких экранов),
  но обычно требует экран на своих пинах/UART, не TFT CYD из коробки.
- **HWiNFO + веб-страница/граббер** — данные можно вытаскивать по JSON/XML, отдавать ESP32 по WiFi.
- Готовые киты на GitHub: ищите **"CYD PC monitor"** / **"ESP32 system monitor TFT"** —
  есть несколько проектов с готовыми прошивками под этот экран.

Данный проект — самодостаточный вариант: ничего, кроме PlatformIO и Python, не требует,
а при желании легко дорабатывается (добавить страницы, WiFi, MQTT и т.п.).

## Безопасность

- Работы с сетью 220V — только при выключенном питании и через изолированные реле.
- Мощность реле должна соответствовать нагрузке (COIL 5V, контакты 10A). Вентиляторы
  куда безопаснее коммутировать по +12V через реле, чем по 220V.
- Гальваническая развязка ESP32 и сети обеспечивается оптопарой модуля реле.
